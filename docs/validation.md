# 验证范围

以下按版本记录截至 2026-10-16 的验证结果。源码重构、原生接口模拟与设备实测不能互相替代。

## 0.4.0 官方 Sign in with ChatGPT（尚未发布）

- 已将 Windows / macOS 桌面订阅入口改为 FastLingo 自己的官方 OAuth 登录，不再启动 Codex CLI、不读取其凭据、不调用 ChatGPT 私有 `backend-api`。旧服务类型标记保留以兼容配置，但须用户重新授权。
- 已通过 166 项自动化测试：54 项核心、19 项构建脚本、60 项前端交互和 33 项原生测试。TypeScript、Vite 生产构建与 Windows GNU 原生构建通过，NSIS 安装包与便携 ZIP 已生成。
- 原生测试包含 11 项认证、11 项 Responses、2 项浏览器入口与 9 项已有测试。认证覆盖状态与回调绑定、PKCE、ID token 验签及身份字段、加密存储、提交取消竞态和刷新账号绑定等；网络与账号使用合成数据，不代表真实授权完成。
- Responses 检查覆盖订阅请求参数、账号模型目录、UTF-8 / SSE 分片、完整成功事件、流中额度错误、拒绝与工具输出、取消和超时等。目录中可见模型不代表本轮已完成实际推理。
- 修复 Windows 登录和用量入口通过 `explorer.exe` 打开网址而显示文件夹的问题，统一使用系统 URL 处理器，在长期运行的主线程派发。新增检查覆盖官方地址限制与授权参数完整保留。最终便携 ZIP 解压启动后，实际点击用量入口打开 Chrome 中的 ChatGPT 页面，点击登录入口打开“使用 ChatGPT 登录 FastLingo - OpenAI”页面；没有新增资源管理器窗口。取消登录后按钮恢复，应用拥有的监听 socket 数量从 1 变为 0。实际运行文件版本为 `0.4.0`，SHA-256 为 `c63a832ba61f21e434585654a39ef760b0b056a8d7fdbf8f5141d81732abcd8b`。
- GitHub 首轮 CI 的唯一失败是用量入口交互测试在异步调用前立即读取计数；改为等待实际原生调用后，定向重复 12 次通过。该修改不改变应用行为。
- 真实 ChatGPT 浏览器授权须用户完成。本轮尚未确认最终包的真实授权、翻译、取消、账号切换或远程撤销；0.3.1 的真实 Codex CLI 翻译记录不作为 0.4.0 SIWC 的成功依据。
- 本轮未实测安装 / 覆盖升级、系统自启、截图完成与取消、多显示器、macOS 真机或移动端。iOS / Android 仍使用自行配置的 API，现有已发布二进制仍为 0.2.0。

## 0.3.1 Codex 订阅翻译

- 本机 Codex 接入默认使用 `gpt-6-luna`，仅支持桌面；仍须用户主动添加服务。登录由 Codex 管理，FastLingo 不读取或复制令牌，不走 API Key 翻译路径。
- 实际复现早期测试包的“尝试使用翻译以外的工具”报错：CLI 0.155.1 会在 `turn.started` 前发出 `item.completed / item.type=error` 配置警告，随后能够正常完成翻译。修复解析器后，非致命通知不显示为译文；真实工具事件仍中止，根级错误与失败仍报错，未知事件单独提示协议不兼容。
- Windows 原生自动化测试 25 项通过，新增启动警告、空结果、真正失败、未知协议及警告后的真实工具调用回归；测试保留取消竞态、阻塞输入、进程超时、输出上限与凭据环境隔离检查。
- 显式运行真实 GPT-6 Luna 订阅测试：`Hello, world.` → `你好，世界。`；`今天的天气很好。` → `The weather is very nice today.`；指令式英文原文按文字翻译，未触发工具事件。真实请求在 300 毫秒后取消，3 秒内结束且子进程已回收。只发送合成测试文本，未调用付费 API Key。
- 150 项自动化测试通过：核心 49 项、构建脚本 19 项、前端交互 57 项、原生 25 项，另显式运行上述真实订阅测试。TypeScript 与生产构建通过；前端 Codex 测试使用模拟接口，其结果与真实订阅测试分开记录。
- 最终便携 ZIP 解压到 `release/smoke-0.3.1-fixed/`，确认运行进程来自该目录，ProductVersion 为 `0.3.1`，可执行文件 SHA-256 为 `5e904c9cc86f801349f0744061bfeaadeceab625e405a64834500fa013e1bb02`。应用界面正常完成 `Hello, world.` → `你好，世界。`；再次请求后按 Esc，状态回到等待翻译且历史计数未增加，原生翻译子进程已退出。最后关闭窗口，FastLingo 进程与可见窗口均消失。
- 0.3.1 未重新验收系统自启、截图完成/取消、安装器安装或覆盖升级。其他平台现有二进制仍为 0.2.0。

## 0.2.1 Windows 截图白屏修复

- 针对截图完成后侧栏出现、其余屏幕仍被白色截图窗口遮挡的反馈，已调整 Windows 原生收尾顺序：先退出全屏，再隐藏窗口，确认隐藏成功后才发送 `capture-reset` 清空预览。重复 `capture_ready` 不再重新显示已就绪的同一会话。
- 自动化验证：38 项核心测试、19 项构建脚本测试和 42 项完整前端交互回归通过。`npm run test:e2e` 耗时约 1.1 分钟；其中截图前端的 8 项定向测试也通过。
- Windows GNU `cargo test`：1 项截图 PNG 单元测试通过。本机测试可执行文件需在忽略的 `target` 目录中补临时 Common Controls v6 manifest 后运行；正式 Release 可执行文件已有 manifest，未因此修改。
- 新增 3 项时序回归：reset 后迟到的图片解码不发送旧 ready；重复开始、拖选和提交只发送一次 ready；reset 后迟到的完成或取消回调不恢复旧截图界面。
- **Windows 便携包实测通过**：从最终 `FastDict-Windows-x64-0.2.1.zip` 解压运行，进程路径为 `release/smoke-0.2.1/fastdict.exe`，实际 ProductVersion 为 `0.2.1`；可执行文件 SHA-256 为 `7e0a1cc88558276137e65a770e9369ef97023b9f72b2f36c18f2905df396ecd2`。
- 实际操作：`Ctrl+Shift+S` → `Esc` 取消两次；拖选 20×20 纯色空白选区后松手完成两次。四次均确认截图窗口不在可见窗口列表，原生 `is_visible=false` 并记录 `capture-overlay-hidden`；侧栏正常恢复，无残留白屏。最后 `Ctrl+Alt+Q` 成功退出。
- 两次完成均实际执行本地 OCR 并显示“未识别到文字”，原文为 0 字符，没有调用真实 API；原有 3 条历史记录及设置保持不变。
- 本轮设备验收仅覆盖当前 Windows 显示器与缩放设置，不代表多屏、其他 DPI 或截图到真实服务商的完整翻译。NSIS 安装程序未执行安装。

## 模拟与设备测试的边界

OCR 测试运行实际打包的 Worker、WASM 和语言模型。常规翻译测试使用本机 HTTP/SSE 服务，没有调用真实付费 API；测试速度不能代表云端服务延迟或翻译质量。0.3.1 曾单独测试真实 Codex 订阅，记录仅适用于旧接入；0.4.0 官方 OAuth 与订阅推理的验收另行记录。

原生接口测试模拟 Tauri 命令与事件，不能替代操作系统截图、窗口可见性、权限、全局快捷键或菜单行为。截图 DOM 被清空不代表原生截图窗口已隐藏，需另行验证窗口完成或取消后的可见性。Mac 界面预览也使用模拟接口。

Windows 曾收到白屏且无法退出的反馈，重启后未复现当时故障，因此尚不能确定原始根因。0.1.1 已加入独立启动恢复界面、存储保护、原生退出、就绪超时和 WebView2 故障监测，并验证实际退出；没有通过清空用户数据规避问题。
